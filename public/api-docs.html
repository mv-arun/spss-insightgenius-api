API Documentation

Call Indico Crosstab from your own app: send survey data, get tables, crosstabs and Excel workbooks back.

REST · JSON .sav .csv .tsv .xlsx .xls Bearer API keys Webhooks v1

Overview

Base URL: https://crosstab.indicolabs.io. Every endpoint is under /v1. The machine-readable contract is at /openapi.json (OpenAPI 3): generate a client from it, or import it into Postman / Insomnia.

A typical integration:

  1. Send the data file: upload it once to POST /v1/files/upload and keep the file_id, or send it with each request.
  2. Look at it: POST /v1/metadata lists the variables, labels and detected question types (single, multi-select, grid, numeric).
  3. Analyse: JSON results from /v1/frequency, /v1/crosstab, /v1/tabulate/preview and the other analysis endpoints.
  4. Export: an Excel workbook from /v1/tabulate (your spec) or /v1/auto-analyze (no spec), as a file, a download link or base64.

The engine is deterministic: the same file and spec always give the same numbers. Only the endpoints under AI Features (and the optional executive summary) use a language model.

Quick start

Upload a file, then make a crosstab and an Excel tabulation from it.

export KEY=sk_live_your_key
export API=https://crosstab.indicolabs.io

# 1. Upload once → file_id (valid 30 minutes after its last use)
FILE_ID=$(curl -s -H "Authorization: Bearer $KEY" \
  -F "file=@survey.sav" $API/v1/files/upload | jq -r .file_id)

# 2. Crosstab as JSON
curl -s -H "Authorization: Bearer $KEY" \
  -F "file_id=$FILE_ID" \
  -F 'spec={"row": "Q1", "col": "Gender"}' \
  $API/v1/crosstab

# 3. Excel tabulation (the .xlsx file)
curl -s -H "Authorization: Bearer $KEY" \
  -F "file_id=$FILE_ID" \
  -F 'spec={"banners": ["Gender", "Region"], "stubs": ["_all_"]}' \
  -o tables.xlsx $API/v1/tabulate

Authentication

Send your API key on every /v1 request:

Authorization: Bearer sk_live_xxxxxxxxxxxxxxxx
  • Keys start with sk_live_ or sk_test_. Only a SHA-256 hash is stored on the server, so a lost key can't be recovered: revoke it and create another (/v1/keys).
  • Each key has a plan (free / pro / business: rate and size limits) and scopes. A key without the scope an endpoint needs gets 403 FORBIDDEN.
  • Keep keys on your server. A browser app should call its own backend, which calls this API.
  • GET /v1/health and GET /downloads/{token} need no key (the download token is the secret).

Sending files

Accepted formats: SPSS .sav, .csv, .tsv, .xlsx, .xls. CSV and Excel files are read into the same structure as SPSS (value labels and question types are inferred), so every endpoint works on every format. The extension of the filename tells the API how to read the file.

Requests that take a file are multipart/form-data. Give the data in one of three ways:

WayHowBest for
fileAttach the file to the request itself.One-off calls.
file_idPOST /v1/files/upload (multipart) once, then send the file_id form field instead of the file.Several calls on the same file. Faster: the file is parsed once and cached.
file_id from JSONPOST /v1/files/upload-base64 with {"filename": "survey.sav", "content_base64": "…"}.Callers that can only send JSON (low-code tools, some gateways).

File sessions

  • A session lasts 30 minutes after its last use: every request with the file_id renews it.
  • GET /v1/files/{file_id} tells you what's in a session and how long it has left (without renewing it). DELETE /v1/files/{file_id} ends it now.
  • An expired file_id gets 404 FILE_NOT_FOUND: upload again.
  • The coding of a session (how each column is read: labels, nets, groups) can be edited with PATCH /v1/files/{file_id}/codebook; later requests with that file_id use it.
POST /v1/files/upload-base64
Content-Type: application/json

{"filename": "survey.sav", "content_base64": "JEZMMkAoIy…"}

→ 200 {"file_id": "4f6c…", "filename": "survey.sav", "format": "sav",
       "n_cases": 1200, "n_variables": 84, "size_bytes": 512304,
       "session_ttl_seconds": 1800, "message": "…"}

JSON fields inside form requests

Structured options travel as a JSON string in a form field: spec (tabulate, crosstab, ANOVA …), options (auto-analyze), codebook, settings. Serialize with json.dumps / JSON.stringify. Invalid JSON is a 400 INVALID_SPEC.

Some endpoints also take a Reporting Ticket (ticket, .docx) or a questionnaire (.docx/.pdf) as extra files.

Getting results

JSON endpoints

Analysis endpoints answer with one envelope:

{
  "success": true,
  "data": { … },                                   // the result
  "meta": { "request_id": "a1b2c3d4", "processing_time_ms": 182 }
}

File endpoints: response_format

/v1/tabulate, /v1/auto-analyze, /v1/convert and /v1/exports/data-workbook produce a file. The response_format form field chooses how you get it:

ValueResponseUse when
file (default)The bytes, with Content-Type and Content-Disposition: attachment; filename="…".You save or stream the file.
urlJSON: data.download_url (valid 15 minutes, no key needed), expires_in_seconds.You hand the file to a user or another service.
base64JSON: data.content_base64.Your platform can only handle JSON.

{
  "success": true,
  "data": {

    "content_type": "application/vnd.openxmlformats-officedocument.spreadsheetml.sheet",

    "expires_in_seconds": 900,

Async jobs & webhooks

Big tabulations can take longer than your HTTP client wants to wait. Add a webhook_url form field to POST /v1/tabulate: the spec is checked straight away (a bad spec is still a 400), then you get 202 Accepted and the work continues in the background.

→ 202 {"success": true, "data": {"job_id": "9b2…", "status": "pending",
        "poll_url": "/v1/jobs/9b2…", "webhook_url": "https://your.app/hooks/crosstab"}}
  • Poll GET /v1/jobs/{job_id} (same key): status goes pending → running → done or failed. Jobs are kept for 1 hour.
  • Or wait for the webhook: we POST JSON to your URL when the job ends, retrying 3 times (1 s, 2 s backoff) on network errors or 4xx/5xx. Answer with any 2xx.
  • A finished job's result.download_url stays valid for 1 hour.
// webhook body (and GET /v1/jobs/{job_id} → data)
{
  "event": "job.completed",                 // or "job.failed"
  "job_id": "9b2…",
  "status": "done",                          // or "failed"
  "result": {
    "download_url": "https://crosstab.indicolabs.io/downloads/…",
    "size_bytes": 48211,
    "expires_at": 1793189440.5
  },
  // failed: "result": {"error": {"code": "VARIABLE_NOT_FOUND", "message": "…"}}
  "timestamp": 1793185840.5
}

The webhook isn't signed: treat it as a notification, and confirm with GET /v1/jobs/{job_id} before you trust its contents. Use a hard-to-guess URL.

Errors

Every error has the same shape. Branch on error.code (stable), show error.message (human-readable, may change). detail repeats the original payload for older clients.

HTTP/1.1 400 Bad Request
{
  "success": false,
  "error": { "code": "VARIABLE_NOT_FOUND", "message": "Stub variables not found: ['Q99']" },
  "detail": { "code": "VARIABLE_NOT_FOUND", "message": "Stub variables not found: ['Q99']" }
}

Limits, retries, CORS

PlanRequests / minuteFile size (/v1/tabulate)
Free105 MB
Pro6050 MB
Business200200 MB
  • File sessions (/v1/files/upload) take files up to 100 MB.
  • Safe retries: send an Idempotency-Key: <uuid> header on a POST. If the same key comes again within 5 minutes, you get the first response back instead of a second run.
  • CORS: browsers may call the API only from the allowed origins. Server-to-server calls aren't affected. Ask us to add your origin, or call from your backend.
  • A request that runs past the processing limit is stopped with 504; use the async mode for large jobs.

Tabulation spec (/v1/tabulate, /v1/tabulate/preview)

Stubs are the questions (one table each); banners are the variables across the top (one column per answer, lettered A, B, C … for significance). All fields are optional except that you'll usually set banners and stubs.

{
  "banners": ["Gender", "Region"],
  "stubs": ["Q1", "Q2", "Q5"],
  "weight": "WEIGHT1",
  "significance_levels": [0.95, 0.90],
  "nets": {"Q1": {"Top 2 Box": [4, 5], "Bottom 2 Box": [1, 2]}},
  "mrs_groups": {"Brand awareness": ["AWARE_A", "AWARE_B", "AWARE_C"]},
  "filters": [{"variable": "Country", "operator": "eq", "value": 1}],
  "output_mode": "banner_sheets",
  "title": "Customer Satisfaction 2026"
}

What to tabulate

FieldType · defaultMeaning

bannersstring[] · noneColumn variables. None = a Total-only table. (banner: a single one, older form.)
mrs_groups{name: string[]}Multi-select questions: one table per group from its 0/1 option variables (% of respondents ticking each).
grid_groups{name: {variables, show}}Grids / batteries. show: any of "t2b", "b2b", "mean".
grid_mode"individual""individual" (a crosstab per item) or "summary" (one compact T2B / mean table).
nets{var: {label: codes[]}}Extra rows merging answers, e.g. Top 2 Box. Nets saved in the codebook are added automatically.
custom_groups[{name, conditions}]Extra banner columns defined by conditions (same form as filters, AND-ed). Banner name: custom_groups_label (default "Custom Groups").
filters[{variable, operator, value}]Only respondents matching all conditions. Operators: eq, ne, gt, gte, lt, lte, in, not_in (value: a list).
table_specs[{table, banners, filters, custom_groups}]Per-table columns and filters. Tables not listed use the top-level ones. Name the tables in stubs / the groups (not _all_).
weightstring · noneWeight variable.

Preview only

/v1/tabulate/preview takes the same spec plus "tables": ["Q1", "Brand awareness"] (up to 50) and returns those tables as JSON (rows, bases, column % and letters), the same numbers the workbook will show.

Recipes

No spec at all: auto-analysis

curl -H "Authorization: Bearer $KEY" -F "file=@survey.sav" \
  -F 'options={"max_banners": 3}' -o report.xlsx $API/v1/auto-analyze

Large job, notified by webhook

curl -H "Authorization: Bearer $KEY" -F "file_id=$FILE_ID" \
  -F 'spec={"banners": ["Region"], "stubs": ["_all_"]}' \
  -F "webhook_url=https://your.app/hooks/crosstab" $API/v1/tabulate
# → 202 {"data": {"job_id": "…"}}; later: GET $API/v1/jobs/<job_id>

JSON-only platform (Zapier, Make, a gateway)

1. POST /v1/files/upload-base64   {"filename": "survey.csv", "content_base64": "…"}  → file_id
2. POST /v1/tabulate  (form: file_id, spec, response_format=url)  → data.download_url

Convert a .sav to CSV with labels

curl -H "Authorization: Bearer $KEY" -F "file=@survey.sav" \
  -F "target_format=csv" -F "apply_labels=true" -o survey.csv $API/v1/convert

Weighted crosstab with two significance levels

curl -H "Authorization: Bearer $KEY" -F "file_id=$FILE_ID" \
  -F 'spec={"row": "Q1", "col": "AgeGroup", "weight": "WEIGHT1", "significance_levels": [0.95, 0.90]}' \
  $API/v1/crosstab
